# mbts Example Project

This is a sample MoonBit project demonstrating how to use `mbts` for TypeScript interoperability.

## Project Structure

```
examples/
├── moon.mod.json       # MoonBit module config
├── moon.pkg.json       # Package config with JS exports
├── main.mbt            # MoonBit source code
├── __jsglue.mbt        # Auto-generated wrappers for generics
├── pkg.generated.mbti  # Generated by `moon info`
└── tmp.d.ts            # Generated TypeScript definitions
```

## Quick Start

```bash
cd examples

# Install dependencies
moon update

# Check & Build
moon check
moon build --target js

# Run
node target/js/release/build/sample.js
```

## Using mbts Commands

### 1. Generate `.mbti` (MoonBit interface file)

```bash
moon info
```

This generates `pkg.generated.mbti` containing all public types and functions.

### 2. Update exports in `moon.pkg.json`

```bash
node ../js/cli.cjs link .
```

This command:
- Reads `pkg.generated.mbti`
- Updates `moon.pkg.json` with exportable functions
- Generates `__jsglue.mbt` for generic function wrappers

### 3. Generate TypeScript definitions

```bash
node ../js/cli.cjs dts .
```

This generates `.d.ts` file from `.mbti`.

## Code Examples

### Structs

```moonbit
pub struct User {
  id : Int
  name : String
  email : String?
}

pub fn create_user(id : Int, name : String) -> User {
  { id, name, email: None }
}
```

Generated TypeScript:
```typescript
export interface User {
  readonly id: number;
  readonly name: string;
  readonly email: string | undefined;
}

export function create_user(arg0: number, arg1: string): User;
```

### Enums

```moonbit
pub enum Status {
  Pending
  Active
  Done
}
```

Generated TypeScript:
```typescript
export interface Status_Pending { readonly $tag: "Pending"; }
export interface Status_Active { readonly $tag: "Active"; }
export interface Status_Done { readonly $tag: "Done"; }
export type Status = Status_Pending | Status_Active | Status_Done;
```

### Generic Types

```moonbit
// Generic type with extern JS binding
type Box[T]

// FFI functions must use @js.Any (no type parameters allowed)
extern "js" fn Box::new(value : @js.Any) -> Box[@js.Any] =
  #| (v) => ({ value: v })

// Public wrapper functions for export
pub fn box_new(value : @js.Any) -> Box[@js.Any] {
  Box::new(value)
}
```

### Generic Functions

```moonbit
// Generic function (cannot be exported directly)
pub fn[T] identity(value : T) -> T {
  value
}
```

When you run `mbts link`, it automatically generates a wrapper in `__jsglue.mbt`:

```moonbit
pub fn __jsglue_identity(arg0 : @js.Any) -> @js.Any {
  identity(arg0)
}
```

## Important Notes

1. **`extern "js" fn` cannot have type parameters** - Use `@js.Any` instead
2. **Generic functions need wrappers for JS export** - `mbts link` generates these automatically
3. **Always run `moon info` before `mbts link/dts`** - The `.mbti` file must be up to date
4. **Set `preferred-target: js`** in `moon.mod.json` for JS-only projects
